Imani referee

Paste the viewing key of any sealed-bid auction on Zcash, and the blocks it ran in. In under a minute this page reads those blocks, counts the bids, finds the winners and the price, and checks that every refund was paid exactly as the rules say. It works on rounds Imani did not run.

Nothing is sent until you say yes. Before any request, the page tells you which servers it would contact and waits for your press. Then it sends only requests for blocks, one per block, saying the network (main or test) and the block number. Your key is never sent anywhere. It is read in this tab and not stored. If you would rather send nothing at all, check from a saved block file instead.

Back to the offline checker, which uploads nothing at all and works from the seller's files.

How it works

  • The blocks come from two block servers run by different operators: a Zcash light wallet server and a public explorer. A block is used only when both give the same block and the same transactions, and each transaction's bytes hash to its id. Both answers are shown with the result.
  • Those servers do not accept requests from a web page, so the site this page came from asks them on its behalf, with the same code as the command line's --fetch. It takes a network and a block number, nothing else, and it has no way to receive a key. On your own computer, tools/referee-serve.ts does the same job.
  • The key is used here, in your browser, with the same decoder and the same checker as the command line tool. The bids, winners, price and refunds are recomputed from the blocks alone, then compared with the refunds the lot really paid.
  • A live check makes network requests, and only after you say yes. A saved block file makes none, and neither does the offline checker. Use one of those when you want nothing to leave your device.
